#   2,28 à 2,59 s [n=3]) : aucun gain mesurable.

#   cinq textes différents), pas de relecture avant écriture dans memory/writer.py.
#   update_chess_game_minis (métadonnée seule, sans embedding) : ~0,5 s [n=3].
# - Le coût vient de torch à 16 threads sur une machine chargée : à 4 threads, chaque
#   écriture passe à ~1,2 à 1,6 s [n=3, autre passage, load 11] (sonde isolée : embedding court

#   un write_sent_message attendu après CHAQUE message envoyé (une photo par diagramme, puis
#   le texte) : ~10 messages × ~2,5 s ≈ 25 s [estimation : mesure unitaire × nombre de
#   messages supposé] étalés entre les envois.
# - Aucun allègement de code livré : aucune piste admise ne gagne quoi que ce soit.
